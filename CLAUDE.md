# CLAUDE.md — Agent Rules for Katja Schedule HA Card

This is the custom Lovelace card for the Katja Schedule HA integration.
It must stay aligned with the main web app at `kmoy007/katja-schedule`.

## Alignment Rule

- **This card must match the web app's UI capabilities.** When the web app adds views, event interactions, drive/flight features, or layout changes, implement them here in the same session.
- Check the main app's `CLAUDE.md` and `project_architecture.md` (in the Claude memory) for the full architecture. The colour, contrast and fade rules the card shares with the web are the main app's `docs/visual-design.md`, and the Family view's rules its `docs/family-month-grid.md`.

## Key Conventions

- **All dates use `_pacificNow()`** — never raw `new Date()`. The schedule is always Pacific time.
- **Deduplicate events** — multi-person events appear in multiple calendar entities. Dedupe by `summary + start time`.
- **Event detail modal** — tap any event to see details. Drive events get "Recheck Drive Time", flight events get "Recheck Flight". Drive time on a drive row aims for its end, as the web's `sheetDriveArrival` does (`_arrivalISOFromEvent`, 0.109.0); `tests/test_drive_row_arrival.py` holds the two together. A Starred chip's sheet is built from its `data-flow-*` attributes, the Starred feed's fields (`_starredChipDetail`): its start and end are the feed's `starts_at` / `ends_at` (0.108.0), never read from `time` here, and a flight's tag and ride answers are the feed's `flight`, `pickup`, `dropoff` and `live_flight`, written into the sheet as the integration's `Flight:`, `Pickup:`, `Dropoff:` lines would be (`_feedFlightLine`, `_feedAnswerLine`, 0.110.0), so the sheet is its list row's (`test_a_starred_flights_sheet_is_its_rows_sheet`). A new feed field goes on the chip too; `test_every_starred_feed_field_reaches_the_chip` fails until it does.
- **The month grid is the exception** — a tap anywhere in a day (date, chip, multi-day bar or empty space) opens that day's popup; the chips are too small to hit on the wall panels. Each event is tappable in the popup. One `.cal-day-hit` button per day column lies over the week; do not put `data-event-idx` on anything in the grid.
- **So is the Family view** — a tap anywhere in a day's row (`.fam-row`, `data-day-date`) opens that day's popup; no line in it carries `data-event-idx`.
- **The preview is the other exception** — with a `tap_action` configured, a tap on any row (or the header) runs that action through HA's `hass-action` event; the panels open a popup with the full day, where each event is tappable. Without one, a row opens its sheet.
- **Recheck calls go through HA WebSocket** (`katja_schedule/refresh_drive`, `katja_schedule/refresh_flight`, `katja_schedule/agent_action`) — never call the Flask API directly from the card.
- **Show traffic warnings** — if `has_traffic` is false, show a red warning. Always show departure time and checked-at timestamp.
- **Words read at 4.5:1 in every theme (card 0.90.0), symbols at 3:1 (0.91.0).** A theme's `muted` (and its own `eventTextSoft`) reads on the card, today, a Day View block, a month day (a weekend's and today's tint included), the sheet, the month's day popup (today's tint and the blocks over the sheet), and the light tints on them; give a new theme its colours as theme values (`todayBg`, `calDayBg`, …), never a `background` in its `customCss`. Words in a fixed hue (a review item's tag, a row's REVIEW tag, the "→ end" chip, the Hide flow, the review queue's Accept and Hide, the error and drive lines) are `var(--label-<name>)`: add one to `LABELS` with its hue, fill and place, and the card makes it read on each theme (`readableOn`). Words in the accent are `var(--accent-ink)`, and grey words on a strong tint (a waiting chip or block, a Hide option, the Hide form's empty preview) are `var(--muted-on-tint)`. A symbol is held to 3:1 (WCAG 1.4.11), not 4.5:1 (card 0.91.0): the ★ of a starred event is `var(--star-mark)`, `STAR` made to read at `SYMBOL_FLOOR` where it sits (`_starMark`), and a Starred bar's ‹ › are `var(--cm)`, its edge's hue made to read on the bar (`_flowTones`). `tests/test_ha_card_theme_contrast.py` runs the card's own `_themeVars` for every theme and measures all of it, every bar `_flowTones` can give in every hue and shade, and every other rule that writes words in a colour, at its opacity (a `SYMBOLS` rule at 3:1; that list is frozen); what still reads below 4.5:1 is its `FAINT_ON_PURPOSE`, the chrome Ken keeps faint (2026-10-06), which only shrinks, and a colour no theme defines fails unless it is one the markup sets on each element (`PER_ELEMENT`). A theme name in the YAML is matched without regard to case (`_themeKey`). The Starred view (its header and 26-week grid, zoomed and empty) is read as drawn by `tests/e2e/test_ha_card_labels.py`; the `none` theme (Home Assistant's own colours) is not. The Starred view is the D Flow grid alone: the A, B, C and E sub-layouts, unused since fr-2026-05-20, went in 0.91.0.
- **Going away is struck through, never faded.** A row its calendar cancelled (`Cancelled: 1`, CANCELLED; a row merely missing from a read says NOT IN CALENDAR and is not struck, Ken 2026-10-13: "Match the web") and a row with a removal waiting keep their words at full strength, struck through in the list, the Day View and the month; only the states Ken keeps faint (hidden, later days of a multi-day event, drive rows, past and outside days) fade, and `EVENT_FADES` in `tests/test_web_person_contrast.py` names each (the card's are not measured as drawn).

## Views

- **Overview** (default): today + tomorrow side by side, 4-week calendar grid below
- **Schedule** (Cards): scrollable day cards, past days hidden
- **Calendar**: 4-week grid starting from today, tap anywhere in a day → day detail modal (the Day View layout for that day)
- **A dark palette at night** (`night_theme`, 0.104.0; the Family spec's "dark palette at night", card-wide): worn while `sun.sun` is below the horizon, `theme` by day (`_followSun`, on every `hass`; it renders only when day and night change). A hand-cycled theme stays until reset; a missing or unavailable `sun.sun` keeps what the card has; an unknown name is a config error. `panel_themes` and the preview's palette are untouched. Tests: `tests/e2e/test_ha_card_night_theme.py`.
- **Family** (`view: family`, or the toggle's Family; fr-2026-09-28-b): a row per day, a column per person (Ken, Katja, Sam, Caleb, House / School), the day's flags under its date, "Needed at home" in a parent's cell, and a Good / Hard / Blocked card for each week. The server lays all of it out (`month_grid.py`), asked for through `katja_schedule/family_month` (integration 0.45.0+); the card only draws it (`_renderFamilyView`) and decides no column, flag or verdict. It opens on this week and the next three, scrolled to today's row once the grid has a size (`_wireFamily`); Month shows a whole month with ‹ Today ›. While it is on screen the calendar fetch reaches back to its first day, so each day's popup has its events. Its chips are LABELS colours (`fam-*`). Its header row and date column stay put while the grid scrolls under them, so they are drawn opaque: the card's colour over the theme's `--modal-bg` (0.105.0; on `theme: none` the card's colour is Home Assistant's, often see-through, and the day before showed through the kitchen screen's header). Tests: `tests/test_ha_card_family.py` (the builder in Node) and `tests/e2e/test_ha_card_family.py` (scroll, tap, chips as drawn)
- **Preview** (`view: preview`, locked only): the compact today list for the small portrait wall panels; from `evening_switch` on, the evening view: what is left of today (two rows at most), an amber Tomorrow bar, then tomorrow (`_previewModel` mode `evening`, `_previewLayout`'s `today`). Behaviour and settings: `README.md` → "Preview (a small panel)". For code changes: its own dark palette (`.pv-host` tokens) whatever the theme; `_previewLayout` decides what is pinned and what scrolls; every render scrolls the list past the ended events except during the 90 s hold after a touch (`_previewHeld`), so the minute ticker can re-render it freely; `_fetchEvents` sets `_fetchFailed` when no calendar loaded. Tests: `tests/test_ha_card_preview.py` (the rules, run in Node) and `tests/e2e/test_ha_card_preview.py` (scroll, button, taps, other views untouched)

## Versioning

- **Bump `CARD_VERSION`** in the JS on every change.
- **Create a GitHub release with a version tag** so HACS detects updates.
- The header shows both card version and app build info: `v0.13.0 · app abc1234 · May 4`

## Structure

- Single file: `katja-schedule-card.js` — no build system, plain JS with Shadow DOM.
- `hacs.json` — HACS metadata, `filename` must match the JS file name.
- Installed via HACS custom repository or manual copy to `config/www/`.
